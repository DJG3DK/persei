## 1. Review gate (`services/commit-reviewer`, `agent/tools/review_gate.py`)

### R15. A new failing test on the branch is reclassified as "pre-existing", and the commit comes back READY

**Severity:** high. **Kind:** integrity. **Since:** `413bcc7`.
**Files:** `services/commit-reviewer/prompt.js` (`_failureMarkers`, `reclassifyPreexisting`, around lines 503–535), `services/commit-reviewer/checks.js` (`applyBaseline`, around line 126), `services/commit-reviewer/reviewer.js` (the call at line 621).

`applyBaseline` marks a whole check pre-existing when it was red on the base
commit for *any* reason; it compares one boolean per check. The comment at
`prompt.js` line ~505 says "failed identically", which nothing checks.
`reclassifyPreexisting` then collects markers (`test:X ... FAIL` lines and
any `tests/…`, `spec/…`, `__tests__/…` path) from **the branch's own
output** of that check, and downgrades every blocking model finding whose
file or text contains one.

So whenever main's suite has any red (a flake is enough), a test file that
is new on the branch and fails there becomes a marker. The model's correct
blocking finding about it becomes `preexisting`, and the verdict is READY.
An agent can also print matching paths into a check's output to excuse an
unrelated finding.

Reproduced: base has `test` red from an unrelated flake and lint green; the
branch adds a bug plus a failing `tests/charge.test.js`, and the model files
a blocking finding on that file. Result: `test.preexisting = true`,
`moved: 1`, `verdict: READY`.

**Fix:** keep the base run's output alongside its boolean. Build markers
from the base output only (or branch markers minus base markers), and never
downgrade on output that appears only on the branch. Better still, record
the base's failing test identifiers in `applyBaseline` and count a branch
failure as pre-existing only when its failing tests are a subset of them.
**Test:** base fails `tests/a.test.js`; branch fails `tests/a.test.js` and
`tests/new.test.js`; a blocking finding on `tests/new.test.js` stays
blocking and the verdict is NEEDS_FIXES. A second case: a branch-only
`test:x ... FAIL` line downgrades nothing.
**Do not touch:** the rule itself for findings that point at the base's own
failures.

### R16. On a host install, a check's timeout never stops its container

**Severity:** high. **Kind:** bug. **Files:** `services/commit-reviewer/sandbox.js` (`dockerArgs`, lines ~455–478: `docker run --rm` with no `--name`, no `--init`; `runSandboxed`, lines ~484–490).

`execFile`'s `timeout` sends SIGTERM to the `docker` CLI, which proxies it
to the container's PID 1. A test runner with no handler ignores it as PID
1, so the container keeps running. When it finally exits 0, the callback
reports success. Reviews are serialised by `inProgress`, so one hung check
freezes every review, and a slow check is recorded as PASS rather than
timed out. The bundle path already does this right: `agent/review_sandbox.py`
`run_check` names the container `rvw-<uuid>` and kills it on timeout and
cancellation.

Reproduced: a `sleep 40` check with `timeoutMs = 3000` was still `Up` at
12 s and returned at 40.5 s with `{"ok":true,"code":0}`.

**Fix:** add `--name rvw-<uuid>` and `--init`; own the timer in
`runSandboxed`, `docker kill` then `docker rm -f` on expiry, and return
`ok: false, code: 124, infrastructure: true` with a "timed out" note.
**Test:** a check that outlives its timeout returns `ok: false`, and
`docker ps -a --filter name=rvw-` is empty afterwards (Docker-gated, in the
`sandbox` CI job).

### R17. One unauthenticated request crashes the commit-reviewer

**Severity:** medium. **Kind:** availability. **Files:** `services/commit-reviewer/reviewer.js` (line ~833 `new URL(req.url, 'http://control.local')` before the secret check; line ~854 `decodeURIComponent` after it; line ~883 binds `0.0.0.0` under `TEKTONIX_BUNDLE=1`; no `uncaughtException` handler).

`GET //` makes `new URL` throw `ERR_INVALID_URL` inside the request
handler; the process exits 1, losing the in-flight review and the queue.
Repeating it keeps the service in a crash loop. An authenticated
`POST /check/a%` does the same through `URIError`.

**Fix:** parse inside try/catch and answer 400; wrap the handler so any
throw is a 500, not an exit.
**Test:** raw `GET //` and authenticated `POST /check/%` both get 400, and
`/health` still answers.

### R18. Test files and referenced files reach the reviewer outside the untrusted-data fence

**Severity:** medium. **Kind:** prompt injection. **Files:** `services/commit-reviewer/prompt.js` (existing test files, lines ~106 and ~324; referenced files, lines ~194, ~235 and ~325; the header comment at lines 7–8 claims all agent-authored material is fenced).

R13's nonce fence covers the diff, commit message and check output. These
two sections are still plain ```` ``` ```` blocks, so a test file the agent
wrote can close the block and add `## HARNESS NOTE (trusted)` as a
top-level heading. Reproduced with a stubbed `fetch`: the fake heading
appeared verbatim outside any `<<<UNTRUSTED-…>>>` fence. Mechanical
failures still block in Node, so only model findings are at risk.

**Fix:** `fenceUntrusted('TEST-FILE', …)` and
`fenceUntrusted('REFERENCED-FILE', …)`, with the per-file `###` headers
inside the fence.
**Test:** a test file containing ```` ``` ```` and a heading ends up between
`<<<UNTRUSTED-TEST-FILE-` and `<<<END-`, with no raw fence surviving.

### R19. Shipping as a pull request pushes the branch tip, not the reviewed commit

**Severity:** low. **Files:** `agent/tools/review_gate.py` (`ship_as_pull_request`, line ~595).

`sha` is used only in the PR body; the push is `+{branch}:refs/heads/{branch}`.
The merge path ships the exact reviewed `tipSha` (R6). Only the agent moves
the branch in that window and a person merges the PR, hence low.

**Fix:** check `rev-parse {branch} == sha`, push `+{sha}:refs/heads/{branch}`,
return `diverged` otherwise.
**Test:** with `push_to_github` stubbed, the refspec carries the sha; a
moved branch returns `diverged`.

**Re-checked and holding:** R2 and R4 (symlinked mounts and copies), R6
(merge ships `tipSha`), R8 (`REVOKE CONNECT`, orphan sweep, Redis command
deny-list), R13 (for diff, commit message, check output and agent replies),
R14 (cookie, `Authorization` and `X-Review-Secret` dropped), the
model router's bearer auth, hard-coded upstream, `finally`-written ledger
line and off-loop trim.

## 2. Agent core and tools

### A19. Auto mode's delete gate no longer stops a heredoc piped to a shell

**Severity:** medium. **Kind:** regression (`9944c99`). **Files:** `agent/deep_agent.py` (`_strip_inert_heredocs`, lines ~550–581, reached from `_deletions_that_lose_work`).

`9944c99` strips the body of a heredoc fed to `cat` or `tee`, deciding that
from the simple command *before* `<<`. It never looks at what follows, so
these all run `rm -rf src` in a real shell and the gate does not ask:

| Command | Gate asks? |
|---|---|
| `cat <<'X' \| bash` / `rm -rf src` / `X` | no |
| `tee /dev/null <<'X' \| sh` / `rm -rf src` / `X` | no |
| `bash <<A; cat <<B` (the `cat` match strips A's body) | no |
| `cat # <<X` / `rm -rf src` / `X` (operator inside a comment) | no |
| `cat '<<X'` / `rm -rf src` / `X` (operator inside quotes) | no |

Every row returned "ask" before `9944c99`. Strict mode still catches them
through the `rm -rf` marker; only auto mode is exposed.

**Fix:** treat a heredoc as inert only when its `cat`/`tee` has a `>` or
`>>` redirect and no `|` (not `||`) follows the operator before the next
`;`, `&&` or newline. Ignore `<<` inside quotes or after `#`. On two heredocs
on one line, consume bodies in order.
**Test:** in `tests/test_auto_approve_gate.py`, `cat <<'X' | bash` and
`tee x <<'X' | sh` with `rm -rf src` bodies report `/workspace/src`; the
existing `cat > x.sh <<'SH'` case stays empty.

### A20. An "already fixed" ending is recorded as a shipped episode

**Severity:** medium. **Kind:** data integrity. **Files:** `agent/nodes/verify_and_ship.py` (`_already_fixed`, lines ~505–520, returns `review_gate_result: state.get(...) or {}`; `_write_episode`, line ~352, treats anything not `None` as shipped), `agent/benchmarks.py` (lines ~133–153), `agent/inbox_alerts.py` (`already_fixed`).

An empty dict is not `None`, so a task that changed nothing is written as
`outcome: shipped`. Consolidation then treats its reflections as confirmed,
and benchmarks count it in `ship_rate` and `cost_per_shipped_median`.
Separately, `_already_fixed` runs on every entry to verify, so resuming a
done inbox task whose alerts its own first run closed also ends "already
fixed", and the operator's feedback never ships.

**Fix:** return `review_gate_result: None` (or an explicit
`outcome: "already_fixed"` that `_write_episode` honours); skip the check
when the task has merged before or `pending_feedback` is set.
**Test:** with `inbox_alerts.already_fixed` mocked true, the episode is not
`shipped`; with `pending_feedback` set, verify does not short-circuit.

### A21. The consolidation prompt has no size limit, carries untrusted GitHub text unfenced, and its tools include `bash`

**Severity:** medium. **Kind:** prompt injection / cost. **Files:** `agent/consolidation.py` (episode lines at ~211–218 embed the full `goal!r` and reflections; `read_only_tools` at ~230 includes `"bash"`; limits at ~76–89; the marker advances only on success at ~300–302), `agent/github_inbox.py` (review requests at ~227–250 have no author filter, unlike Dependabot PRs at ~215).

Inbox goals carry up to 20k characters of PR body plus 6k of code, and a
goal may be 80k, so 50 episodes can overflow the context. Any outsider's PR
that requests a review flows into the prompt whose output becomes
`/memories/AGENTS.md`, which every later task reads. A failure that repeats
(overflow, or the budget guard tripping after a paid answer) leaves the
marker on the same batch and retries hourly at up to $2 each.

**Fix:** truncate goals (~500 characters) and cap reflections; wrap
episodes in a nonce fence as R13 did; drop `bash`; after K failures on one
batch, skip past it; apply `_author_allowed` to review requests.
**Test:** 50 episodes with 80k goals build a prompt under a fixed length
that contains the fence; the tool list has no `bash`.

### A22. Consolidation can overwrite memory edits made while it runs

### A23. Web-search spend is never attributed to a session

**Severity:** low. **Files:** `agent/tools/web_search.py` (`web_search(..., *, metadata=None)`, line ~168), `agent/tools/planning_tools.py` (`_run_web_search`, line ~125; the tool, line ~506).

**Test:** the planning `web_search` passes `metadata={"agent_session_id": …}`.

### A24. Delete forms auto mode still does not ask about

**Severity:** low. **Files:** `agent/deep_agent.py` (`_deletions_that_lose_work`).

## 3. Backend API, auth and data

### B25. A successful login from the same IP resets the brute-force limit for every account

**Severity:** medium (multi-user only). **Files:** `agent/rate_limit.py` (`clear_rate_limit`, lines ~184–193 pop the whole `(ip, action)` bucket); callers in `agent/routers/auth.py` (lines ~188, 212, 274, 295, 333) and `agent/routers/passkeys.py` (lines ~60, 114).

Four wrong passwords for the victim, one correct login as yourself, repeat.
Reproduced: 30 victim guesses, zero 429s; without the interleaved login,
the 6th try was refused. The same trick resets `password-recheck`.
**Fix:** on success clear only that account's failures; key failures by
`(ip, action, account)` or keep a per-account counter. Same for
`verify-2fa`, `password-recheck` and `passkey-login`. Also correct the
module docstring ("5 then locked").
**Test:** the interleaving sequence gets a 429 on the victim's 6th guess.

### B26. Passkey sign-in accepts an assertion made on a sibling origin

**Severity:** medium (domain installs with a parent `WEBAUTHN_RP_ID`, or loopback). **Files:** `agent/passkeys.py` (`relying_party`, lines ~91–113).

The expected origin is whatever the request's `Origin` header says, and
any `*.WEBAUTHN_RP_ID` is accepted; `localhost` covers every port. A
hostile page on `chat.example.com` (or `localhost:5173`) can run the
ceremony against the shared RP ID and relay the assertion with a matching
forged `Origin`. Reproduced both ways: 200 and a session cookie, skipping
password and TOTP.
**Fix:** derive the expected origin from what the console is served at —
`Host` plus `X-Forwarded-Proto` from a trusted proxy, or a configured
`PUBLIC_URL` / `WEBAUTHN_ORIGINS` — and refuse a mismatched `Origin`.
Correct the docstring's "cannot be phished", and say in `SECURITY.md` that
a passkey replaces password plus TOTP, admins included.
**Test:** both cross-origin cases return 400/401.

### B27. A passkey survives a password change and a password reset

**Severity:** low. **Files:** `agent/auth.py` (`change_password`, ~675–691; `reset_password`, ~896–934).

Sessions are revoked, `agent_passkeys` is not, so a planted passkey still
signs in after the reset the code itself calls the moment trust is lost.
**Fix:** delete passkeys on reset; on change, delete or ask. **Test:** a
passkey sign-in after a reset is 401.

### B28. The `.env` editor's newline guard misses other Unicode line breaks (M-3 incomplete)

**Severity:** low (admin-only). **Files:** `agent/env_config.py` (`_format_value` ~211 and `set_keys` ~293–295 refuse only `\n`, `\r`, NUL; `_write_env` ~239 re-reads with `str.splitlines()`).

`\x0b`, `\x0c`, `\x1c`–`\x1e`, `\x85`, `\u2028` and `\u2029` survive the
guard and become line breaks on the next save. python-dotenv still reads
them as one quoted value, but the router's pm2 loader
(`services/model-router/ecosystem.config.js`) parses line by line;
reproduced writing `MODEL_ROUTER_ALLOW_UNAUTHENTICATED=1` into the router's
`.env`.
**Fix:** refuse any value with `len(v.splitlines()) > 1` or a Cc/Zl/Zp
character; split the file on `"\n"`. **Test:** parametrize over the
separators.

### B29. A web-push endpoint can be any URL (blind SSRF with a success oracle)

**Severity:** low. **Files:** `agent/routers/push.py` (`push_subscribe` ~58–68, `push_test` ~85–110), `agent/push.py` (`_send_blocking` ~141–184).

Any signed-in account can subscribe `http://127.0.0.1:<port>/…`; the test
send POSTs there and reports `sent: 1` on a 2xx. Reproduced as a restricted
user.
**Fix:** require `https` and refuse loopback, private, link-local and
metadata addresses with `url_guard`'s check, resolved at send time.
**Test:** loopback and RFC 1918 endpoints get 400.

### B30. The code that finishes TOTP enrolment can be replayed once at login

**Severity:** low. **Files:** `agent/auth.py` (`confirm_totp_setup`, ~787–797).

It verifies with `valid_window=1` but stores the wall-clock step, not the

### B31. On loopback, other localhost ports share the session cookie, and the WebSockets check no `Origin`

## 4. Desktop app and release (`app/`, `release.yml`)

### D28. Auto-updating from Tektonix to Persei on Windows leaves no shortcut

**Severity:** high. **Kind:** upgrade bug. **Since:** `0cb1525` (v0.9.4, shipped).
**Files:** `app/src-tauri/windows/hooks.nsh` (lines 12–25); tauri-bundler's `installer.nsi` (`CreateOrUpdateStartMenuShortcut` and `CreateOrUpdateDesktopShortcut` return early when `$UpdateMode = 1` and `$WixMode = 0`); tauri-plugin-updater 2.13 (`/P /UPDATE /R` arguments).

The Tektonix updater runs the Persei installer with `/UPDATE`. The
pre-install hook silently uninstalls Tektonix, which removes its `.lnk`
files (the hook's own comment says so). The installer, in update mode,
then skips both shortcut functions. Data survives; every way to launch the
app does not. Quit now really stops the app (`d834c30`), so after a quit or
a reboot it looks uninstalled.

**Fix:** in `PREINSTALL`, set a flag when the Tektonix key exists; add
`NSIS_HOOK_POSTINSTALL` that, when the flag is set *or* the Start-menu
shortcut is missing, sets `$UpdateMode 0` and calls both shortcut
functions (or `CreateShortcut` directly). The "or missing" half is what
repairs copies that already took v0.9.4. Add a CHANGELOG line telling
affected users where the app is (`%LOCALAPPDATA%\Persei\`).
**Test:** a Windows CI job beside `verify_windows_installer.sh` that installs
0.9.3 silently, runs the new installer with `/P /UPDATE /S`, and asserts
`Start Menu\Programs\Persei.lnk` exists and the `Uninstall\Tektonix` key
does not.

### I24. The updater signing key is in the environment of unpinned tooling

**Severity:** medium. **Kind:** supply chain. **Files:** `.github/workflows/release.yml` (line ~228 `cargo install trusted-signing-cli --locked` with no version; ~230 it becomes `signCommand`; ~241–242 `TAURI_SIGNING_PRIVATE_KEY` in the same step's env; ~364–367 the Linux `tauri build --bundles appimage,deb` also has the key and downloads linuxdeploy at build time), `.github/workflows/ci.yml` (~445, `container: ivangabriele/tauri:debian-bookworm-20` pinned by tag).

OIDC; pin the CI container by digest.
**Test:** a workflow lint that fails on `cargo install` without a version or
rev, or on the signing key in any step that runs `tauri build`.
